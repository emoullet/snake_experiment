# Interface actions: operator workflow and participant screen

This document describes the interface implemented in the working tree. The calibration interface is served by `web_app.py`, `templates/index.html` and `static/app.js`. The session interface is served by `session_web_app.py`, `templates/session_index.html` and `static/session_app.js`. The participant screen uses `templates/participant_index.html` and `static/participant_app.js`.

All source paths below are relative to `src/snake_experiment_ui/snake_experiment_ui/`. Python controller methods use `Class.method` notation. In the tables, **Action chain** follows **JavaScript handler → HTTP endpoint → Python route function → controller method**. Unless otherwise stated, requests are `POST`, operator clicks are handled by `SessionInterface.bindActions` through `post`, and routes belong to `session_web_app.py`. `{mode}` is `baseline` or `snake`; `{phase}` is `training` or `recording`. The backend validates actions even when a button is enabled in the browser.

## Shared state, navigation and protection

- `TargetCalibrationApp.connect` and `SessionInterface.connect` open `/ws`. The respective `state_websocket` routes publish `create_app.snapshot` and `create_session_app.combined_snapshot`. `update` and `render` refresh labels, values and availability. The connection indicator reports Connected/Disconnected; it does not command the robot.
- The workflow strip is a status indicator, not clickable navigation. `SessionInterface.render` selects the active screen from check-up, enrollment and experiment state in that order. The discovery, training and recording screens are reused for both modes.
- Most actions are disabled while a request is pending (`busy`), during transitions, or when required state is missing. Errors appear in a toast. Read-only badges, process summaries, pose errors and paths do not trigger actions.
- The launch-selected robot is shown in the interface. Calibration, check-up, enrollment/resume and experiment preparation check robot/tool-frame compatibility. A robot mismatch cannot be bypassed with the environment-mismatch checkbox. Calibration files without robot provenance must be recreated. Simulation and hardware can share a calibration for the same robot, subject to frame checks.
- Protected session commands require fresh, ready overload-protection state. `protect_commands` applies the guard to mode checks, Go-to and selected block/stack actions. Starting an inactive stack, including discovery bootstrap, can occur before telemetry is available; robot commands remain locked until protection is ready.

| Control | Availability and effect | Action chain |
| --- | --- | --- |
| “Stop retreat” | Requires fresh protection state in `waiting_retreat`, `translating`, `waiting_clear` or `rotating`. Cancels automatic recovery, including the stationary delay before translation. | `bindActions`/`post` → `/api/protection/stop` → `protection_command` → injected `protection_action("stop")`. |
| “Rearm protection” | Requires fresh state, `rearm_ready`, no pending cleanup and no request in progress. Explicitly rearms protection; it does not automatically restore manual control or recording. | `bindActions`/`post` → `/api/protection/rearm` → `protection_command` → injected `protection_action("rearm")`. |

`SessionInterface.renderProtection` displays recovery phase, reason, target and configuration. An overload pauses arm/gripper commands and interrupts affected control/recording. Resume explicitly after rearming: activate discovery control to create a new segment, or use the trial recovery controls as appropriate.

## Calibration

Controls come from `templates/index.html` and pose cards generated by `TargetCalibrationApp.renderCaptureShells`. Clicks use `TargetCalibrationApp.bindActions`/`post`; all routes in this section belong to `web_app.py`.

| Control | Availability and effect | Action chain |
| --- | --- | --- |
| “Start/Stop experiment stack” | Label follows stack state; unavailable during startup/shutdown or a pending request. Starts or stops the interface-owned ROS stack. | `bindActions` → `/api/stack/start` or `/api/stack/stop` → `control_stack` → `StackManager.start` or `stop` (`stack_manager.py`). |
| “Activate/Deactivate baseline mode” and “Activate/Deactivate snake mode” | Starts the selected joystick mapper or stops the active mapper. The opposite mode is disabled while one is active; both buttons are disabled during transitions. | `bindActions` → `/api/modes/{mode}` or `/api/modes/{mode}/deactivate` → `activate_mode` or `deactivate_mode` → `ModeManager.activate` or `deactivate` (`mode_manager.py`). |
| Seven “Record …” buttons | Require `can_capture` and no pending request: an active mode and recent `/ee_pose`. Capture validates the frame and pose values, then stores/replaces the in-memory capture. | `renderCaptureShells` creates each button; `bindActions` → `/api/poses/{pose_id}` → `capture_pose` → `CalibrationState.capture` (`calibration.py`). IDs: `target_1`, `target_out_1`, `target_2`, `target_out_2`, `target_3`, `target_out_3`, `starting_point`. |
| “Save calibration” | Requires `can_save`: seven captures in a common frame and an active mode. Validates and writes the calibration; the toast reports the filename. | `bindActions` → `/api/calibrations` → `save_calibration` → `CalibrationState.calibration_document`, then `CalibrationStorage.save` (`storage.py`). |
| Pose details disclosure | Locally expands/collapses a captured pose's frame, mode, position, quaternion and timestamps. | HTML `<details>` created by `poseDetails` and preserved by `renderCapturedPose`; no HTTP request. |

`renderCurrentPose` displays the latest pose, age and timestamps from `CalibrationState.snapshot`. Waiting/Live/Stale and capture badges are read-only. The save path is not editable here. Current files are `calibrations/latest_calib_explorer.json` and `calibrations/latest_calib_kinova.json`, selected by the launched robot; saving one does not replace the other.

## System check-up

Controls are defined in `templates/session_index.html`. Mode cards share handlers with different `{mode}` values.

| Control | Availability and effect | Action chain |
| --- | --- | --- |
| “Start/Stop experiment stack” | Available outside stack transitions and pending requests. Stopping also interrupts active Go-to and mode control. | `bindActions`/`post` → `/api/stack/start` or `/api/stack/stop` → `stack` → `CheckupController.start_stack` or `stop_stack` (`checkup.py`). |
| “Check/Retry baseline mode” and “Check/Retry snake mode” | Require an active stack and no competing mode test. Retry appears after failure. Starts the mapper and diagnostics, then waits for joystick observations and operator confirmation. | `bindActions`/`post` → `/api/checkup/modes/{mode}/start` or `/retry` → `start_mode` or `retry_mode` → `CheckupController.start_mode` or `retry_mode`. |
| “Yes, validate” / “No” | Shown while a mode awaits confirmation. Accepts observed behavior or fails/stops the mode so it can be retried. | `bindActions`/`post` → `/api/checkup/modes/{mode}/confirm`, `accepted=true/false` → `confirm_mode` → `CheckupController.confirm_mode`. |
| “Go to starting point” / “Go to target 1/2/3” / “Go to target 1/2/3 (retreated)” | Require `go_to.available` and no active motion. A confirmation precedes movement to the four original poses or the corresponding `target_out_1/2/3` retreat poses. | `bindActions`/`post` → `/api/checkup/go-to`, `pose_id` → `start_checkup_go_to` → `CheckupController.start_go_to` → `GoToController.start` (`go_to.py`). |
| “Stop motion” | Shown during active Go-to; interrupts it. | `bindActions`/`post` → `/api/checkup/go-to/stop` → `stop_checkup_go_to` → `CheckupController.stop_go_to` → `GoToController.stop`. |
| “Reset” | Available outside pending requests. Cancels motion, stops mode and stack, and resets check-up state. | `bindActions`/`post` → `/api/checkup/reset` → `reset` → `CheckupController.reset`. |
| “Validate system check-up” | Requires `can_validate`: both mode checks passed and all seven Go-to poses reached. Also checks provenance, prepares the report, stops mode/stack and advances to participant enrollment. | `bindActions`/`post` → `/api/checkup/validate` → `validate` → `CheckupController.validate`. |

`renderMode` displays diagnostics and instructions. Clicking a diagnostic `<summary>` is prevented by `bindActions`. Go-to counts, errors and validation blockers are informational. Go-to supervision distinguishes missing valid feedback, total timeout and insufficient progress; `goToTimeoutMessage` explains the termination reason. These deadlines are supervised independently of browser polling.

## Session folder and participant enrollment

Available after check-up validation. `renderBrowser` and `renderEnrollment` generate folder and resume entries.

| Control | Availability and effect | Action chain |
| --- | --- | --- |
| “Browse folders” | Opens the folder browser at its configured root. | `browse` → `GET /api/session/browse?path=` → `browse` → `EnrollmentController.browse` (`enrollment.py`). |
| Folder entry / “Up” | Navigates the browser; Up requires a parent. Navigation alone does not select a session parent. | `bindActions` → `browse(path)` → `GET /api/session/browse?path=…` → `browse` → `EnrollmentController.browse`. |
| “New folder” / “Create” | Requires a name (HTML maximum: 100 characters). Creates a child of the displayed directory, refreshes the listing and clears the field. | `createFolder` → `/api/session/folders`, `parent_path`, `name` → `create_folder` → `EnrollmentController.create_folder`. |
| “Use this folder” | Selects the displayed directory, closes the dialog, resets the form and generates a pseudonym. | `bindActions` → `/api/session/root`, `path` → `select_root` → `EnrollmentController.select_parent`; then `regeneratePseudonym` → `/api/session/pseudonym/regenerate` → `regenerate_pseudonym` → `EnrollmentController.generate_pseudonym`. |
| Dialog “Close” | Closes the dialog and clears New folder without changing the selected parent. | `closeBrowser`; no HTTP request. |
| “Change folder” | Resets enrollment and reopens the browser. Reset calls cancel: a participant created in this enrollment is removed together with its CSV row. | `bindActions` → `/api/session/reset` → `reset_session` → `EnrollmentController.reset`; then `browse("")`. |
| “Pseudonym” / “Regenerate” | The six-character field is read-only. Regenerate requests a new unique code. | `regeneratePseudonym` → `/api/session/pseudonym/regenerate` → `regenerate_pseudonym` → `EnrollmentController.generate_pseudonym`. |
| Consent, handedness, experience and impairment fields / “Create participant” | Required form fields; editing alone sends no request. Valid submission creates participant files, an `experiment_state.csv` row and the assigned experimental plan. | `createParticipant` → `/api/session/new` → `create_participant` → `EnrollmentController.create_participant`. |
| “I acknowledge these differences…” / “Resume” | The checkbox is sent with Resume when environment differences require acknowledgment. Resuming preserves saved session files and adds the current check-up report. Robot compatibility remains mandatory. | `bindActions`/`post` → `/api/session/resume`, `pseudonym`, `acknowledge_mismatch` → `resume_participant` → `EnrollmentController.resume_participant`. |
| “Cancel” | Shown for a ready participant. Removes a newly created participant's folder/CSV row; a resumed session is preserved. | `bindActions`/`post` → `/api/session/cancel` → `cancel_participant` → `EnrollmentController.cancel`. |
| “Launch experiment” | Requires `enrollment.can_launch`. Prepares the selected participant's experiment and advances to the experiment sequence. | `bindActions`/`post` → `/api/session/launch` → `launch_session` → `EnrollmentController.launch`, which invokes the configured experiment preparer. |

Paths, warnings, partial sessions, environment differences and participant summaries are informational. After session POSTs, `post` fetches `GET /api/state` to refresh the combined state. Participant manifests retain the original robot configuration and record creation/resume configurations in `robot_history`; acknowledging a legacy environment does not assign provenance retrospectively.

## Presentation and experiment sequence

`renderExperiment` displays the assigned plan, block order, mode, phase, folder, attempt count, status and process summary. Finishing a block returns here to start the next one.

| Control | Availability and effect | Action chain |
| --- | --- | --- |
| Presentation “Display” | Available for pending/showing/completed presentations with no active block. Shows or replays the presentation on the participant screen from the beginning. | `bindActions`/`post` → `/api/experiment/presentation/show` → `show_presentation` → `ExperimentController.show_presentation` (`experiment.py`). |
| Presentation completion button | Requires presentation status `showing`. Records operator confirmation. Missing video permits manual confirmation and records a warning. | `bindActions`/`post` → `/api/experiment/presentation/complete` → `complete_presentation` → `ExperimentController.complete_presentation`. |
| “Start/Resume/Retry discovery/training/recording” | Only the next unfinished block is startable, with eligible status and no stack operation. Presentation must be completed or `legacy_skipped`. Creates/resumes the block folder and starts the stack; training/recording also activate the mode mapper. Opens the corresponding discovery, training or recording screen. | `bindActions`/`post` → `/api/experiment/blocks/{block_id}/start` → `start_experiment_block` → `ExperimentController.start`. |
| “Start stack” / “Stop stack” / “Restart stack” in Robot processes | Use `can_start_stack`, `can_stop_stack`, `can_restart_stack`. Available only between blocks, without motion, mapper or recorder activity. Manage interface-owned processes without changing session progress or starting a mapper/recorder. Restart requires clear protection; stop remains available during overload. | `bindActions`/`post` → `/api/experiment/stack/start`, `/stop` or `/restart` → `start_experiment_stack`, `stop_experiment_stack` or `restart_experiment_stack_between_blocks` → `ExperimentController.manage_experiment_stack`. |

Stack stop completes when owned processes exit. A subsequent launch may display “Waiting for ROS graph cleanup” while DDS still advertises departed nodes. The bounded wait does not adopt or kill other processes. State updates continue during that wait. These actions do not suspend or close the participant session.

## Discovery

`renderDiscovery` displays instructions, process state and MCAP segments. Finishing requires a confirmed mode explanation and at least one valid segment containing messages on all required topics.

| Control | Availability and effect | Action chain |
| --- | --- | --- |
| “Show mode explanation” | Shows/replays the selected mode's video on the participant screen from the beginning, including after earlier confirmation. | `bindActions`/`post` → `/api/experiment/blocks/{block_id}/explanation/show` → `show_mode_explanation` → `ExperimentController.show_mode_explanation`. |
| “Explanation done” | Requires explanation status `showing`. Confirms the explanation. Missing video permits manual confirmation and records a warning. | `bindActions`/`post` → `/api/experiment/blocks/{block_id}/explanation/complete` → `complete_mode_explanation` → `ExperimentController.complete_mode_explanation`. |
| “Activate/Deactivate mode and recording” | Activation requires a completed explanation; protection checks also apply. Starts joystick mapping and MCAP together, or stops them and closes the current segment. | `bindActions`/`post` → `/api/experiment/blocks/{block_id}/control`, `active=true/false` → `set_experiment_control` → `ExperimentController.set_control`. |
| “Restart stack” | Requires browser confirmation. Restarts the owned stack and restores the preceding control state when permitted; an active segment may be closed. | `bindActions`/`post` → `/api/experiment/blocks/{block_id}/restart-stack` → `restart_experiment_stack` → `ExperimentController.restart_stack`. |
| “Stop and return” | Interrupts the block and returns to the experiment sequence; the block can be resumed. | `bindActions`/`post` → `/api/experiment/blocks/{block_id}/abort` → `abort_experiment_block` → `ExperimentController.abort`. |
| “End discovery” | Requires `experiment.can_end` and browser confirmation. Completes the block and returns to the experiment sequence. | `bindActions`/`post` → `/api/experiment/blocks/{block_id}/end`, `confirmed=true` → `end_experiment_block` → `ExperimentController.end`. |

After overload interruption, rearm protection and activate mode/recording explicitly to start a new segment. See the [session setup checklist](../src/snake_experiment_ui/README.md#study-configuration-before-enrollment) for required study content and media.

## Training and recording

`renderTraining` and `renderRecording` call `renderTrialView` with `phase=training` and `phase=recording`. Routes and controller methods below use the corresponding phase name. Unless specified, endpoint paths start with `/api/experiment/blocks/{block_id}`. Controller methods belong to `ExperimentController`.

| Control | Availability and effect | Action chain |
| --- | --- | --- |
| “Activate control” | Shown when control is inactive; disabled during recording, Go-to or a pending request. Explicitly restores control when permitted by protection. | `bindActions`/`post` → `/control`, `active=true` → `set_experiment_control` → `set_control`. |
| “Prepare next trial and move to start” | Requires `awaiting_prepare` and unresolved trials. After confirmation, prepares the next trial and moves to `target_out_{target_start}`. Manual control is suspended during Go-to and restored afterwards when permitted. | `bindActions`/`post` → `/{phase}/prepare` → `prepare_training_trial` or `prepare_recording_trial` → same-named controller method → `_prepare_trial` / `start_go_to`. |
| “Start recording” | Requires `awaiting_start_pose` or `ready`, a start pose within thresholds, no active Go-to and the correct active mapper. Starts an MCAP attempt. There is no separate Participant ready button in the current UI. | `bindActions`/`post` → `/{phase}/start` → `start_training_attempt` or `start_recording_attempt` → same-named controller method. |
| “Stop recording” | Enabled during acquisition. Stops the attempt as invalid; incidents may require review before retry/deviation resolution. | `bindActions`/`post` → `/{phase}/stop` → `stop_training_attempt` or `stop_recording_attempt` → same-named controller method. |
| “Signal incident occurrence” | Shown/enabled during recording. Each click records one timestamped occurrence without requiring a description or immediately invalidating the attempt. | `bindActions`/`post` → `/{phase}/incidents`, no text payload → `add_training_incident` or `add_recording_incident` → same-named controller method. |
| Incident descriptions / “Validate attempt” / “Invalidate attempt” | Shown at `incident_review_required`, after acquisition. Every occurrence needs a description (HTML maximum: 2,000 characters). Submits the descriptions and whether incidents invalidate the attempt. Validating incidents does not override a technically invalid result. | `bindActions` submit handler/`post` → `/{phase}/incidents/review`, `descriptions=[{id,text},…]`, `invalidates_attempt=false/true` → `review_training_incidents` or `review_recording_incidents` → same-named controller method. |
| “Retry trial” / “Continue with deviation” | Shown at `decision_required`. Retry prepares the same trial for another attempt; deviation explicitly accepts it with a recorded protocol deviation and advances. | `bindActions`/`post` → `/{phase}/resolve`, `decision=retry` or `advance_with_deviation` → `resolve_training_attempt` or `resolve_recording_attempt` → same-named controller method. |
| “Go to starting point” / “Go to target 1/2/3” | Require `experiment.go_to.available`, no active motion and no pending incident review. Confirmation precedes motion to `starting_point` or `target_out_1/2/3` (unlike the target poses used during system check-up). Manual control is suspended/restored around motion. | `bindActions`/`post` → `/go-to`, `pose_id` → `start_experiment_go_to` → `start_go_to` → `GoToController.start`. |
| “Stop motion” | Shown during active Go-to; stops that motion. | `bindActions`/`post` → `/go-to/stop` → `stop_experiment_go_to` → `stop_go_to` → `GoToController.stop`. |
| “Restart stack” | Requires confirmation. Restarts the owned stack and restores block control when permitted. An ongoing acquisition is stopped as invalid. | `bindActions`/`post` → `/restart-stack` → `restart_experiment_stack` → `restart_stack`. |
| “Stop and return” | Interrupts the block, stops owned processes and returns to the experiment sequence. An active acquisition is stopped as invalid. | `bindActions`/`post` → `/abort` → `abort_experiment_block` → `abort`. |
| “End training” / “End recordings” | Requires `experiment.can_end`: all trials succeeded or were explicitly accepted with deviation. Confirmation completes the block and returns to the experiment sequence. The final block completes the sequence and stops the stack. | `bindActions`/`post` → `/end`, `confirmed=true` → `end_experiment_block` → `end`. |

Start/target linear and angular errors, trial history, incident history and technical outcomes are read-only projections of `ExperimentController.snapshot`. Reaching the configured target tolerances for the required dwell can automatically stop acquisition; `/ws` reports the outcome without another click. Incident review remains necessary when occurrences were reported. The active threshold values are defined by `success_thresholds` in `config/experiment.yaml`.

The `/{phase}/ready` endpoints still exist (`confirm_training_ready` / `confirm_recording_ready` → `training_participant_ready` / `recording_participant_ready`), but `renderTrialView` does not render a control calling them.

## Participant screen and previews

Open `/participant` on the participant display. It displays the general presentation, mode explanation/discovery content, or trial/control content according to the current experiment stage. `participant_projection` extends `ExperimentController.participant_snapshot` with overload warnings. `GET /participant/api/state` and `/participant/ws` expose that projection.

- Operator Display and Show mode explanation actions issue new playback requests. Each click restarts its video; ordinary state updates do not restart playback. If audible autoplay is blocked, use the participant video's Play control. Videos are served by `GET /participant/video` and `/participant/video/mode/{mode}`.
- The six camera viewpoint buttons select the shared viewpoint of the participant joystick previews locally. The choice lasts until reload; `preview.default_view` in `config/participant_interface.yaml` supplies the initial camera viewpoint. The previews illustrate the selected robot's mappings and send no ROS commands.
- Camera access on entering the participant trial/control screen may require browser permission. Camera and media controls are local browser interactions, not robot commands.
- A confirmed overload episode displays an orange warning while the stack is active and plays the local warning sound once per episode. If blocked by autoplay, “Play warning sound” retries playback. Reconnects and retreat-phase updates do not replay it. A newly loaded page warns about an ongoing episode. `sounds.overload.duration_sec` controls the maximum playback duration (default 3 seconds); backend restart is required after changing it. The alarm takes priority over the success cue while leaving video, camera and previews running.
- `/participant/3d-preview` is a dedicated read-only preview. Its `/api/config`, `/api/state`, `/model.urdf`, `/assets/{asset_id}` and `/ws` endpoints are beneath `/participant/3d-preview`. Fresh valid arm joint states drive the model; otherwise a demo pose is used. Changing the selected robot requires relaunching the interface.

## Generic block fallback

For a phase other than discovery/training/recording, `renderActiveBlock` renders a generic fallback screen with read-only parameters. Restart stack, Stop and return and End use the same `/restart-stack`, `/abort` and `/end` action chains described above.
